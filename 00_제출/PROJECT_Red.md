### 한 줄 소개
제주에서 작은 사업체를 운영하는 사람이 지역별 방문객과 소비 자료를 보고, 손님이 적은 시기에 누구에게 어떤 상품을 언제 홍보할지 정하며, 앞으로 3개월의 홍보 일정과 실행 결과를 관리할 수 있게 돕는 시스템

## 2. 프로젝트 배경 및 목적

### 2.1 해결하려는 문제
제주 전체 관광객 수가 늘거나 줄었다는 통계만으로는 지역의 카페나 체험 활동을 제공하는 업체가 언제 손님이 줄고 어떤 고객과 상품에 힘을 쏟아야 할지 알기 어려움 이 프로젝트는 작은 사업체 운영자가 지역별 방문·소비 자료를 직접 모으고 뜻을 이해해 실행 계획을 세우는 데 어려움이 있을 것이라는 가정에서 시작함 실제로 얼마나 어려운지, 지금은 어떤 방식으로 홍보하는지는 사업체 운영자와의 인터뷰로 알아볼 예정이며 현장 조사는 아직 끝내지 않았음 지역별로 손님이 적은 시기인 비수기, 업종별로 돈을 쓰는 비중, 내국인과 외국인의 차이, 시간대별로 돈을 쓰는 모습을 함께 살펴보고 실제 홍보 일정표를 만드는 데 쓸 필요함

### 2.2 프로젝트 목적
제주 전체의 읍·면·동별 방문·소비 자료를 비교해 지역마다 손님이 적은 시기와 다시 늘어나는 시기를 알아봄 먼저 사용해 볼 2개 또는 3개 지역을 고르고, 카페 또는 체험 활동을 제공하는 업종 중 하나를 고름 고른 지역과 업종에 맞춰 홍보할 달, 내국인·외국인 중심의 고객 구분, 알릴 상품 후보, 살펴볼 시간대와 주변 관광지를 함께 이용하게 할 방법을 이유와 함께 제안함 사업체가 이를 앞으로 3개월의 홍보 일정표로 만들고 고치며 실행 결과를 기록하도록 도움 자료를 살펴본 결과가 실제 선택에 도움이 되는지 확인함 먼저 사용할 지역·업종·함께할 사업체는 확인 필요 상태

### 2.3 기대효과
- 사용자 관점: 작은 사업체 운영자가 여러 통계를 따로 이해하는 부담을 줄이고, 손님이 적은 시기에 언제 누구에게 홍보할지 정하는 데 필요한 이유를 찾도록 도움 홍보 계획을 세우는 시간이 줄었는지, 추천 내용을 이해하고 선택했는지 확인할 예정이며 효과는 아직 확인되지 않음
- 운영자 또는 사업 관점: 지역마다 계절에 따라 달라지는 방문과 소비 모습을 바탕으로 홍보 행사와 주변 관광지를 함께 이용하게 하는 방법을 시험함 실제로 선택하고 실행했는지, 클릭·예약·쿠폰 사용처럼 구할 수 있는 기록을 보고 도움이 되었는지 살펴봄 매출이 늘어나는 것은 기대하는 효과일 뿐 반드시 이루어진다고 약속하거나 이미 얻은 결과로 쓰지 않음

## 4. 핵심 서비스 시나리오

### 지역별 비수기 분석을 활용한 3개월 마케팅 계획 수립
1. 작은 사업체 운영자가 자신의 지역과 업종을 고르고 앞으로 3개월의 홍보 계획을 만들어 달라고 요청함
2. 시스템은 사용할 수 있는 기간의 지역별 방문·소비 자료를 비교함 손님이 적은 시기와 다시 늘어나는 시기, 내국인·외국인의 소비 차이와 시간대별 소비 모습을 자료를 가져온 곳·자료의 기준기간과 함께 보여줌 이를 바탕으로 홍보 시기·대상, 운영자가 확인할 상품 후보와 주변 관광지를 함께 이용하게 할 방법을 제안
3. 사업체 운영자는 제안을 실제 판매 상품과 운영할 수 있는 조건에 맞게 고르고 고쳐 월별 홍보 일정표에 저장함 실행한 활동과 구할 수 있는 클릭·예약·쿠폰 사용 건수 등을 기록하며, 기록이 없으면 아직 구하지 못한 상태로 남김
4. 시스템은 저장한 계획과 실제로 선택하고 실행한 내용을 다시 볼 수 있게 함 계획을 세우는 데 걸린 시간과 모은 활동 결과의 숫자를 정리해, 사업체별로 사용한 결과를 보고서에 쓸 때 필요한 근거를 제공

## 6. 개발 범위

### 필수 구현 범위
- F01부터 F03까지의 기능을 만듦 제주 읍·면·동별 방문객 수의 변화와 돈을 쓰는 모습을 비교함 자료가 정확하고 빠진 내용은 없는지와 함께할 사업체를 구할 수 있는지에 따라, 먼저 사용해 볼 범위를 2개 또는 3개 지역의 카페 또는 체험 활동을 제공하는 업종 중 하나로 좁힘 지도·월별 비교 화면, 추천 이유가 표시된 실행 방법, 3개월 일정표의 저장·다시 보기·수정, 사용 기록과 짧게 정리한 사례를 제공함 실제 사업체에서 사용하는 시험은 함께할 사업체를 구한 범위에서 진행함 구하지 못하면 사업체 운영자를 따로 모집해 쓰기 편한지 확인하는 방식으로 바꿈 팀에서 기능을 시험한 결과, 대표 사용자가 쓰기 편한지 확인한 결과, 실제 사업체에서 사용한 결과를 나누어 보고

### 선택 구현 범위
- F04의 근거를 바탕으로 한 AI 설명·보고서 첫 작성본 만들기, 일정표·보고서를 파일로 내려받기, 먼저 사용해 볼 업종·지역 늘리기를 검토함 외부 홍보·예약 서비스와 자동으로 자료를 주고받는 기능은 이용 권한과 개발할 수 있는 조건을 확인한 뒤 선택적으로 검토

### 제외 범위
- 지금 이동하는 사람 수와 얼마나 붐비는지 보여주는 기능, 관광객 한 사람씩의 이동·결제를 따라가며 확인하는 기능, 자동 광고 실행·결제·예약을 대신하는 기능, 매출이 반드시 늘어난다는 약속, 제주 전체 업종에서 실제로 사용하는 것은 제외함 카드 소비 자료와 통신회사의 방문자 집계를 단순히 나눈 값을 실제 1인당 소비액이나 방문자 중 구매한 사람의 비율로 해석하지 않음 이 서비스가 매출을 바꿨다는 확인되지 않은 결과나 고객 한 사람씩의 행동을 예상한 결과도 제공하지 않음

## 10. 결과물 및 성공 기준

### 예상 결과물
- 실행 가능한 정보시스템: 지역별로 손님이 많고 적은 시기를 보여주는 지도, 월별 방문·소비 비교 화면, 이유가 설명된 실행 방법, 앞으로 3개월의 홍보 일정표와 사용 기록 관리 화면
- 분석·설계 산출물: 필요한 기능과 조건을 자세히 적은 문서, USE-CASE 다이어그램(사용자와 기능의 관계 그림), 화면설계, ERD(저장할 자료의 관계 그림), 자료를 가져온 곳·자료의 뜻·정리 기준과 추천 규칙을 적은 문서
- 소스코드 및 GitHub 저장소: 자료 처리·분석·서비스를 만드는 코드, 기능별로 고친 기록, 실행 안내와 같은 과정을 다시 따라 할 수 있는 집계 자료의 처리 순서 비공개 자료는 제외함
- 테스트 결과, 배포 시스템, 매뉴얼: 자료가 맞는지, F01부터 F03까지의 기능과 이용 권한 제한이 제대로 작동하는지 시험한 결과, 사용자가 먼저 사용해 볼 수 있는 운영 환경, 사용자·운영자 안내서, 구한 사용 기록을 바탕으로 한 사례 보고서
- 최종 발표자료 및 개인 포트폴리오: 해결하려는 문제, 자료를 쓴 과정, 추천 이유, 먼저 사용해 보거나 쓰기 편한지 확인한 결과와 그 결과로 알 수 없는 점을 담은 발표자료, 팀원별로 맡은 일과 참여한 내용을 정리한 기록

### 성공 기준
- 핵심 기능 정상 동작: F01부터 F03까지의 기능에서 고른 지역·기간·업종에 맞는 결과가 보여야 함 각 분석·추천에서 자료를 가져온 곳·기준기간·수를 세고 합친 기준을 확인할 수 있어야 함 자료가 없거나 제공 기준이 달라 비교할 수 없으면 그 사실을 분명히 표시하고, 숫자나 추천 이유를 마음대로 만들지 않음
- 대표 사용자 시나리오 완료: 사용자가 지역·업종을 고르고 추천 이유를 확인한 뒤, 앞으로 3개월 계획을 작성·수정·저장하고 다시 볼 수 있어야 함 먼저 시험할 때는 기존 방식과 비교해 계획을 세우는 데 걸린 시간, 제안을 선택하고 실행했는지를 기록함 시험할 대상 수와 숫자로 정할 목표는 인터뷰와 처음 상태의 측정이 끝난 뒤 정함 클릭·예약·쿠폰 사용은 실제로 구한 기록만 보고함
- 데이터 저장·조회 검증: 자료마다 지역을 나타내는 코드를 맞게 연결했는지, 월별로 수를 세고 합쳤는지, 소비 자료의 제공 기준이 같고 서로 겹치는 기간의 자료만 사용했는지 확인함 검사할 일부 자료로 계산한 결과가 화면과 같아야 함 저장한 계획·사용 기록은 다시 보아도 남아 있어야 하고, 모으지 못한 값을 0건으로 표시하지 않아야 함 다른 사업체의 비공개 계획·기록은 권한 없이 볼 수 없어야 함
- 배포 및 시연 완료: 먼저 사용해 보는 환경에서 대표 사용 순서대로 실행하고 필수 기능의 잘못된 부분을 고친 뒤, 시험 결과·사용 안내서·작동 모습을 보여줄 자료를 준비함 결과 보고에서는 쓰기 편한지 확인한 시험과 실제 사업체에서 사용한 결과를 나눔 매출 변화에 영향을 줄 수 있는 날씨·연휴·기존 홍보 같은 다른 요인과, 조사한 일부 대상만으로는 알 수 없는 점을 분명히 적음
