## Actor와 이동 구조

- **사업체 운영자:** 본인 사업체의 계획·기록과 분석·제안·사례·자료 현황 조회
- **서비스 운영자:** 자료·기준 관리와 권한을 받은 사업체의 계획·기록 처리
- 별도의 상위 Actor는 두지 않는다.
- 미로그인 직접 접근은 로그인으로 이동한다. 사업체 운영자의 관리 화면 직접 접근은 한눈에 보기로 이동한다.
- Screen ID의 C는 공통 화면, B는 사업체 계획·기록 업무군, A는 자료·기준 관리, Pnn은 팝업·패널을 뜻한다. B 화면의 서비스 운영자 접근은 권한을 받은 사업체로 제한한다.

- 인증 완료 후 허용된 메뉴만 표시

| ⑦ | 취소 클릭 → 변경 내용 저장 취소 → SCR-A-001 복귀 |
| ⑧ | 기준 저장 클릭 → 권한·입력 검사·서버 저장 → 기준·홍보 제안 갱신 |
| ⑨ | 저장 성공 → 완료 메시지 생성 → 추천 기준 저장 완료 알림 표시 |

**화면 상태:** ■ 정상   □ 결과없음   ■ 오류   □ 처리불가   ■ 완료

**이동:** 기준 저장 → 서버 저장·제안 재계산 → SCR-A-001 기준 요약 갱신

- 저장한 기준·근거는 이후 홍보 제안 조회에 반영
- 필수값 오류는 해당 입력란에 표시
- 저장 실패 시 기존 적용 기준과 입력값을 유지

## 구현 범위와 현재 시안의 구분

화면별 Description은 구현할 서비스의 행위·처리·결과를 설명한다. 현재 Make 시안에서 확인한 동작과 서버 구현 완료는 구분한다.

| 항목 | 확인한 범위 |
| --- | --- |
| 필수 기능 | F01 방문 추이, F02 소비 비교·월별 제안, F03 일정·실행 결과, 운영 지원(CSV·추천 기준) |
| 추가 화면 기능 | 제안 일괄 담기, 기록 자동 채움, 활용 사례·결과(UC11), 데이터 반영 현황(UC12) |
| 제외 | F04(UC06 보고서 초안 작성)는 이번 제출의 구현 범위에서 제외 |
| 인증·저장 | Make는 임시 계정과 브라우저 저장으로 시연. 실제 서버 인증·권한·저장은 목표 동작 |
| 월별 직접 추가 | 해당 월의 일정 계획을 작성·저장하는 기능. 홍보 제안 카드를 새로 생성하는 기능으로 설명하지 않음 |
| 일괄 담기 | 미추가 제안만 저장하며 기존 계획 유지. 중복 제외, 실패 시 추가 전 상태 복구 |
| 기록 자동 채움 | 최초 작성은 계획 날짜·채널·준비 내용 등을 기본값으로 제공. 실행 여부·날짜·활동은 운영자가 실제 내용으로 확인·수정 |
| 성과 입력 | 소요 시간·클릭·예약·쿠폰 수는 자동 수집하지 않음. 빈칸은 미확보·미측정, 0은 실제로 확인한 0건 |
| 활용 사례 | 사례명·효과 수치는 고정된 검증 전 예시. 실제 성과로 인용하지 않음. 별도 사례 상세·등록·검색 화면은 없음 |
| 데이터 현황 | 등록 자료가 0건이어도 추천 기준 상태를 포함해 25%가 표시됨. 실자료 적용률로 해석하지 않음. 마지막 확인일 9월 29일은 고정 문구 |
| CSV | 현재 시안은 출처·등록 행 수를 저장하고 그래프는 예시 자료를 표시. CSV 행이 분석에 실제 적재되는 것으로 설명하지 않음 |
| 지표 해석 | 지역 방문 집계를 가게 손님 수로 해석하지 않음. 서로 다른 모집단의 방문·소비 자료로 전환율·1인당 소비를 계산하지 않음 |
