# Red 유스케이스 다이어그램

[프로젝트 기준 문서](Red_PROJECT.md) v1.1의 기능·범위와 2026-09-21에 제공한 유스케이스 강의자료 21장을 바탕으로 다시 그린 설계 초안임 기존 ‘사용자’·‘사업체 운영자’·‘서비스 운영자’의 역할과 이용 범위를 유지하며 구현 완료를 뜻하지 않음

[StarUML 편집 원본 열기·다운로드](Red_USECASE.mdj) · [SVG 미리보기](assets/Red_USECASE.svg) · [PNG 미리보기](assets/Red_USECASE.png)

수정 기준은 `Red_USECASE.mdj`임 StarUML의 액터·유스케이스·시스템 경계·연관·include 모델과 각 요소의 배치 정보를 담은 편집 원본임 모델 이름은 UC 번호와 행위를 나타내는 명사 중심으로 정리하고, F01부터 F04까지의 대응과 세부 조건은 아래 표와 모델 설명에 기록함

StarUML의 **File → Open**으로 원본을 연 뒤, 모델 탐색기의 **유스케이스 모델** 아래에서 다음 도면을 선택해 편집함

| 도면 | 표시하는 기능 | 이용 액터 |
| --- | --- | --- |
| 01 공통 분석·제안 조회 | UC01·UC02와 필수 포함 기능 UC10 | 사용자·사업체 운영자·서비스 운영자 |
| 02 홍보 계획·실행 기록 | UC03부터 UC06까지 | 사업체 운영자·서비스 운영자 |
| 03 자료·추천 근거 관리 | UC07·UC09와 필수 포함 기능 UC08 | 서비스 운영자 |

세 도면은 하나의 시스템을 나누어 보여주는 관점이며 화면 이동 순서나 서로 다른 시스템을 뜻하지 않음 같은 이름의 액터는 원본에서 동일한 모델을 참조함 고유 액터는 3개, 유스케이스는 10개이며 각 도면의 사각형은 같은 시스템의 경계임

StarUML 7.1.1에서 원본을 읽고 세 도면의 SVG·PNG 내보내기가 성공하는 것을 확인함 앱의 미등록 상태에서는 내보낸 그림에 워터마크가 표시되므로, 위 통합 미리보기는 원본 모델·좌표에서 별도로 생성함 앱 내보내기 이미지를 수정한 결과는 아니며 원본과 미리보기의 액터·기능·관계를 대조함 앱 화면에서 수동 편집 후 다시 저장하는 동작과 Obsidian의 읽기 화면은 직접 확인하지 못함 통합 그림의 화면 표시와 문서의 표·링크 구조를 별도로 검증함

실선은 액터와 기능의 이용 관계, 점선 화살표는 필수 포함 관계, 노란 타원은 선택·검토 중인 기능을 뜻함 액터는 시스템 경계 밖에, 유스케이스는 안에 배치함 원본을 수정하면 미리보기도 같은 내용으로 갱신함

## 사용자와 범위

| 액터 | 역할 | 이용 범위 |
| --- | --- | --- |
| 사용자 | 새로 추가한 일반 조회 역할이며 세부 범위는 설계 가정 | UC01·UC02를 조회하며 두 기능에 UC10이 포함됨 사업체의 비공개 일정표·실행 기록과 운영 관리 기능에는 연결하지 않음 |
| 사업체 운영자 | 카페 또는 체험 활동 업체 운영자·홍보 담당자 | UC01부터 UC06까지 이용하며, UC01·UC02에는 UC10이 포함됨 UC06은 도입할 경우에만 제공함 |
| 서비스 운영자 | 프로젝트 팀의 개발·자료 분석·검증 담당자 | UC01부터 UC06까지와 자료 등록·추천 근거 관리를 이용함 UC01·UC02에는 UC10, UC07에는 UC08이 포함됨 비공개 사업체 계획·기록은 권한 또는 동의가 있는 범위에서만 사용함 |

‘사용자’는 요청에 따라 기존 두 액터와 별도로 추가함 역할이 구체적으로 지정되지 않아 이번 초안에서는 일반 조회 사용자로 해석함 관광객 대상 상품·예약 기능이나 일반 공개 서비스 도입을 확정한 뜻은 아니며, 실제 제공 대상과 접근 권한은 별도로 정함 기존 두 운영자의 이용 범위와 유스케이스 열 개는 유지함

그림의 실선은 기능 이용 관계이며, 화면 이동이나 처리 순서를 뜻하지 않음 사업체 운영자는 실제 사업 활동을 수행하고 시스템에는 그 기록을 입력함 시스템이 광고 게시·결제·예약을 대신 실행한다는 뜻이 아님

## 기능 대응표

| 유스케이스 | 사용자가 수행하는 일 | 프로젝트 기능 | 구현 범위 |
| --- | --- | --- | --- |
| UC01 | 지역과 기간을 고르고 지역별 방문 분석·지도·월별 그래프를 조회함 | F01 | 필수 |
| UC02 | 지역 방문과 업종별 소비를 비교하고 홍보 시기·대상·상품 후보·주변 관광지 활용 제안을 근거와 함께 조회함 | F02 | 필수 |
| UC03 | 추천 내용을 실제 상품과 운영 조건에 맞게 골라 3개월 홍보 일정표를 작성·수정·저장·다시 보기함 | F03 | 필수 |
| UC04 | 계획 수립에 걸린 시간, 추천을 선택했는지, 실행 날짜와 구할 수 있는 클릭·예약·쿠폰 사용 기록을 입력함 | F03 | 필수 |
| UC05 | 저장한 계획과 실제 활동·사용 결과를 비교하고 짧게 정리한 내용을 조회함 | F03 | 필수 |
| UC06 | 검증한 분석 결과와 사용 기록으로 추천 이유 설명·보고서 초안을 작성함 | F04 | 선택·검토 중 |
| UC07 | 운영자가 확보한 CSV 자료를 시스템에 등록함 자동 수집이나 외부 API 연동을 뜻하지 않음 | F01·F02 운영 지원 | 필수 기능을 위한 자료 준비 |
| UC08 | 등록할 자료의 기간·집계 기준·지역 코드·누락값·제공 기준의 일관성을 검증함 비교할 수 없는 자료는 그 사실을 표시함 | F01·F02 운영 지원 | UC07에 반드시 포함 |
| UC09 | 확인한 분석 결과를 바탕으로 추천 기준과 이유를 관리함 | F02 운영 지원 | 필수 기능을 위한 근거 관리 |
| UC10 | 시스템이 조회·추천에 쓰인 자료의 출처·기준기간·집계 기준을 결과와 함께 표시하여 사용자가 확인할 수 있게 함 | F01·F02 공통 | UC01·UC02에 반드시 포함 |

각 조회·추천에는 자료의 출처·기준기간·집계 기준을 함께 제공함 지역 방문객 집계를 개별 가게의 손님 수로 표현하지 않으며, 구하지 못한 실행 기록을 0건으로 바꾸지 않음

## include 관계

- `UC01 지역별 방문 분석 조회 → «include» → UC10 자료 출처·기준 표시`
- `UC02 방문·소비 비교와 홍보 제안 조회 → «include» → UC10 자료 출처·기준 표시`
- `UC07 CSV 자료 등록 → «include» → UC08 자료 기준·누락값 검증`

UC01·UC02를 이용하면 출처·기준기간·집계 기준을 결과와 함께 표시함 필수인 것은 시스템의 표시 동작이며, 사용자가 확인 버튼을 누르거나 별도 화면을 반드시 열어야 한다는 뜻은 아님 이를 분명히 하려고 UC10의 이름을 ‘자료 출처·기준 확인’에서 ‘자료 출처·기준 표시’로 고침 기존 문서의 필수 출처 표시 요구를 따로 드러낸 것이며 새로운 사업 기능을 추가한 것이 아님

자료를 등록할 때 검증을 반드시 포함한다는 뜻이며, 화살표는 포함되는 기능인 UC08·UC10을 향함 검증을 통과하지 못한 자료를 정상적인 비교 자료로 취급하지 않음

F01·F02·F03을 순서대로 include로 연결하지 않음 저장한 일정표를 다시 보거나 수정할 때 모든 분석을 매번 새로 실행해야 한다는 요구사항은 없기 때문임

## 선택 기능과 AI 에이전트

F04는 현재 프로젝트 문서에 있는 선택 기능으로 표시함 선택 구현이라는 이유만으로 `<<extend>>` 관계를 추가하지 않음 실행 중 어떤 조건에서 기존 기능을 확장하는지가 정해져야 해당 관계를 사용할 수 있음

강의자료의 단골 고객 할인은 멤버십 가입 조건과 주문할 책 입력 완료라는 확장 시점이 있고, 신용카드 지불은 신용카드를 선택한 경우라는 조건이 있음 현재 F04에는 어느 기본 유스케이스의 어느 시점에서 확장할지가 정해져 있지 않아 독립된 선택 유스케이스로 표시함 이후 확장 관계를 정의할 경우 화살표는 추가 기능에서 기본 유스케이스를 향하도록 작성함

대화에서 제안한 AI 에이전트의 가게 조건 질문·계획 초안 작성·수정은 아직 도입이 확정되지 않아 이번 기준 다이어그램에는 넣지 않음 F04를 AI 에이전트 기반 기능으로 확대하기로 결정하면 프로젝트 문서와 유스케이스 범위를 함께 갱신함

## 이번 그림에 추가하지 않은 내용

- 로그인·회원가입: 접근 권한 보호는 필요하지만 구체적인 인증 방식과 화면은 아직 정하지 않아 별도 기능으로 추가하지 않음
- 외부 데이터 플랫폼 액터: 현재 계획은 운영자가 CSV를 확보해 등록하는 방식이며, 외부 플랫폼과 자동으로 통신하는 구조는 확정되지 않음
- 외부 AI 서비스 액터: AI 사용 여부와 제공 업체·연결 방식이 정해지지 않아 추가하지 않음 시스템 내부 기능을 별도 사용자로 표시하지 않음
- 자동 광고 실행·결제·예약 대행, 실시간 혼잡도, 개인별 이동·결제 추적, 매출 증가 보장: 기존 프로젝트의 제외 범위를 유지함

## 검토 기준

- 기존 액터 두 역할과 F01부터 F04까지는 프로젝트 기준 문서와 맞추고, 추가한 ‘사용자’의 일반 조회 범위는 설계 가정으로 구분함
- 일정표의 작성·수정·저장·다시 보기와 실행 기록·결과 비교가 빠지지 않았는지 확인함
- 필수 기능, 선택 기능, 운영 지원과 제외 범위를 구분함
- 실선 관계와 include 화살표의 방향, 한글 표시와 그림 잘림을 확인함

| 포함 관계 | UC01 → UC10, UC02 → UC10, UC07 → UC08이며 화살표가 필수로 포함되는 기능을 향하는지 확인함 |
| 확장·일반화 관계 | 확장 조건과 시점 또는 역할의 상속 관계가 정해지지 않았으므로 추가하지 않음 선택 구현과 실행 중 조건부 확장을 구분함 |
| 시스템 경계와 도면 | 같은 시스템을 3개 도면으로 나누고 동일 액터 모델을 재사용함 액터는 경계 밖, 유스케이스는 경계 안에 위치하는지 확인함 |
| 명세 조건 | 출처·기간·집계 기준 표시, 자료 부족·기준 불일치 안내, 미확보 기록과 0건의 구분, 비공개 기록의 권한·동의 조건을 유지함 |
| 원본과 표시 검증 | JSON 식별자·참조·소유 관계, 도면별 모델 연결, StarUML 7.1.1 로드·내보내기, 통합 미리보기의 한글·선·화살표·잘림을 검증함 |
