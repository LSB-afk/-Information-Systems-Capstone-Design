## 1. 어떻게 바꾸면 되는지 먼저 정리

**기존 UC의 번호를 유지하면서 두 기능을 새로 추가하고, 월별 제안·일괄 담기·기록 자동 채우기는 기존 UC 설명에 반영하는 안을 권장한다.**

| 구분          | 수정할 내용                                                                                            |
| ----------- | ------------------------------------------------------------------------------------------------- |
| 새 타원 추가     | **UC11 활용 사례·결과 조회**, **UC12 데이터 반영 현황 조회**                                                       |
| 기존 타원 확장    | UC01 지역별 방문·소비 분석 조회, UC02 월별 홍보 제안 조회, UC03 3개월 홍보 일정표 관리, UC04 사용·실행 기록 관리, UC05 계획 이행·실행 결과 조회 |
| 기존 운영 기능 유지 | UC07 CSV 자료 등록, UC08 자료 기준·누락값 검증, UC09 추천 기준·근거 관리, UC10 자료 출처·기준 표시                             |
| 기존 중복 정리    | 방문 비교·소비 비교는 UC01에, 실행 기록 입력은 UC04에, 자료 출처 표시는 UC10에 통합                                           |
| 기존 제외 범위 유지 | UC06 보고서 초안 작성과 온톨로지는 이번 수정안에 포함하지 않음                                                             |
| Actor 정리    | 사업체 운영자와 서비스 운영자만 직접 연결함 ‘사용자’ Actor와 이를 향한 일반화 관계는 만들지 않음                                        |

이 방식이면 대표 UC는 **11개**다. 기존 대표 UC 10개에서 UC06을 제외하고, UC11·UC12를 추가한 수다. 새로 만든 두 UC는 기존 화면 안의 기능에 연결하므로 별도 화면을 추가할 필요가 없다.

## 4. 새로 추가할 UC 두 개

### UC11 활용 사례·결과 조회

- **목적:** 비슷한 사업체가 어떤 홍보 활동을 했고 어떤 결과를 기록했는지 참고
- **Actor:** 사업체 운영자, 서비스 운영자
- **연결 화면:** 한눈에 보기, 홍보 제안의 ‘실제 활용 사례와 창출 효과’ 영역
- **현재 화면 항목:** 지역, 사업체 이름, 실행 활동, 결과 표현, 해석 시 주의사항
- **기본 흐름:** 화면 진입 → 사례 카드 표시 → 활동과 결과·검증 상태 확인
- **현재 확인 범위:** 고정된 예시 카드 조회 사례 검색·상세 팝업·등록·수정·공개 승인 기능은 확인되지 않았으므로 추가하지 않음
- **향후 실제 자료를 사용할 때:** 사례 출처·측정 기간·비교 기준과 이용 동의 범위를 확인한 자료로 교체

타원 설명에 넣을 문구:

> 사업체의 홍보 활동과 기록된 결과를 사례별로 조회하고, 예시 여부와 결과 해석의 한계를 확인함 현재 시안의 사례는 검증 전 예시이며 실제 성과를 입증한 자료가 아님

UC05는 **내 사업체의 계획과 실행 기록을 비교하는 기능**, UC11은 **참고할 사례를 읽는 기능**이므로 별도로 둔다. 실제 사례가 확보되지 않은 상태를 숨기지 않고, 효과 자동 계산·성과 보장 기능으로 표현하지 않는다.

### UC12 데이터 반영 현황 조회

- **목적:** 화면의 분석 자료가 예시인지, 등록된 자료가 있는지 확인
- **Actor:** 사업체 운영자, 서비스 운영자
- **연결 화면:** 한눈에 보기의 ‘실제 데이터 반영 현황’ 영역
- **현재 화면 항목:** 월별 지역 방문, 업종 카드 소비, 내·외국인 소비 비중, 추천 기준, 표시된 반영률, 등록 건수·행 수, 확인 날짜
- **기본 흐름:** 한눈에 보기 진입 → 항목별 자료 상태와 등록 현황 표시 → 자료의 준비 상태 확인
- **현재 확인 범위:** 등록 이력에 따른 상태 표시 실제 분석값 교체 여부까지 검증하는 기능은 아님
- **제출 설명의 기준:** 등록됨과 분석에 적용됨을 구분하고, 근거가 없는 실제 적용률은 확정 수치로 적지 않음

타원 설명에 넣을 문구:

> 분석에 사용하는 자료 항목의 예시 여부와 등록 현황을 조회함 실제 자료가 분석에 적용됐는지는 별도로 확인하며, 현재 시안의 반영률을 검증된 실데이터 적용률로 해석하지 않음

UC10은 **개별 분석·제안의 자료 출처와 기준을 표시하는 기능**, UC12는 **자료 항목별 준비·등록 상태를 모아 보는 기능**으로 구분한다.

## 5. 기존 UC에 추가할 상세 동작

### UC02 월별 홍보 제안 조회

1. 홍보 제안 선택 → 선택 지역의 추천 기준에 맞는 제안 조회 → 월별 열에 표시
2. 추천 근거 선택 → 판단 이유·출처·운영 조건 조회 → 근거 패널 표시
3. 해당 월에 제안이 없음 → 빈 상태 안내 표시 → 다른 월을 확인하거나 직접 계획 작성 가능

현재 화면은 2026년 10월부터 12월까지로 고정되어 있다. 임의의 시작 월을 골라 기간을 바꾸는 기능은 추가로 확인되지 않았으므로 구현된 동작처럼 작성하지 않는다.

### UC03 3개월 홍보 일정표 관리

1. **개별 담기:** 일정에 담기 선택 → 제목·예정일·채널·준비 내용 자동 채움 → 확인·수정 후 저장
2. **일괄 담기:** 한 번에 담기 선택 → 현재 추천 조건에 맞고 아직 담지 않은 제안만 선택 → 기존 계획을 유지하면서 일정에 추가·저장
3. **월별 직접 작성:** N월 마케팅 제안 직접 추가 선택 → 해당 월의 계획 작성 팝업 표시 → 입력·저장 → 해당 월 일정에 반영
4. **수정:** 계획 수정 선택 → 기존 계획 불러오기 → 수정·저장 후 목록 갱신
5. **삭제:** 계획 삭제 선택 → 연결 기록도 삭제된다는 확인 안내 → 확인 시 계획과 연결 기록 삭제
6. **예외:** 이미 담은 제안은 중복 추가하지 않음 저장 실패 시 기존 계획 유지

같은 일괄 담기 동작의 진입 버튼이 세 곳에 있다.

| 화면 | 버튼 이름 |
| --- | --- |
| 한눈에 보기 | 제안 한 번에 담기 |
| 홍보 제안 | 남은 제안 N개 한 번에 담기 |
| 3개월 홍보 일정표 | 홍보 제안 자동 채우기 |

버튼마다 새 UC를 만들지 않고 모두 UC03에 연결한다. 직접 추가 버튼도 현재 저장 대상이 일정표의 계획이므로 UC03에 연결한다. **‘홍보 제안 생성·편집·삭제’라는 독립 기능은 현재 동작에서 확인되지 않았다.**

### UC04 사용·실행 기록 관리

1. 일정표의 실행 기록 또는 실행 결과 조회의 기록 입력 선택 → 연결된 계획 확인
2. 최초 작성이면 계획의 날짜·활동·추천 채택 정보를 기본값으로 채움 기존 기록이 있으면 저장값을 불러옴
3. 사업체 운영자가 실제 실행 여부·날짜·활동을 확인하고 필요한 부분 수정
4. 확보한 소요 시간·클릭·예약·쿠폰 사용 수와 수집 방법 입력 → 입력값 검사 → 저장 후 실행 결과 목록 갱신
5. 미확보 결과는 빈칸으로 유지 확인된 0건과 구분
6. 잘못된 값이나 저장 실패 시 오류 표시 → 입력 내용 유지 → 수정·재시도

**자동 채우기는 기존 계획의 내용을 가져오는 동작이다.** 계획 소요 시간을 자동 측정하거나 외부 광고·예약·쿠폰 서비스에서 결과를 수집하는 기능은 확인되지 않았다. 현재 팝업은 실행 여부를 ‘실행함’, 실제 실행 날짜를 예정일로 기본 표시하므로 저장 전에 실제 내용 확인이 필요하다는 조건을 명시한다.

### UC05 계획 이행·실행 결과 조회

1. 실행 결과 조회 선택 → 일정표의 계획과 연결된 기록 표시
2. 준비한 계획 수, 기록 작성 수, 미기록 계획 수 확인
3. 사용 결과 요약 선택 → 계획과 실제 활동, 확보한 결과를 비교한 요약 표시
4. 기록 없음과 미확보 결과를 구분하고, 기록이 없다는 이유로 실행 실패라고 판단하지 않음

계획이 있으면 결과 수치를 입력하지 않아도 목록을 조회할 수 있다. 결과 조회 때마다 UC04 입력을 강제하는 include 관계는 만들지 않는다.

## 6. Actor와 연결선

### Actor는 두 개만 배치

| Actor | 직접 연결할 UC |
| --- | --- |
| 사업체 운영자 | UC01, UC02, UC03, UC04, UC05, UC11, UC12 |
| 서비스 운영자 | UC01, UC02, UC03, UC04, UC05, UC07, UC09, UC11, UC12 |

- ‘사용자’ Actor와 이를 향한 일반화 관계는 삭제하거나 추가하지 않는다.
- 두 Actor에서 공통 UC로 각각 실선을 연결한다.
- 서비스 운영자에게 UC03·UC04·UC05를 연결할 때 다음 권한 주석을 붙인다.

> 사업체 계획·기록은 관리 권한을 부여받은 사업체 범위에서만 조회·처리함

현재 Make에도 서비스 운영자의 허용된 사업체 계획·기록 관리 안내가 있다. 이 연결을 모든 사업체의 비공개 자료에 대한 무제한 접근으로 설명하지 않는다.

### include는 세 관계 유지

| 출발 | 관계 | 도착 |
| --- | --- | --- |
| UC01 지역별 방문·소비 분석 조회 | «include» | UC10 자료 출처·기준 표시 |
| UC02 월별 홍보 제안 조회 | «include» | UC10 자료 출처·기준 표시 |
| UC07 CSV 자료 등록 | «include» | UC08 자료 기준·누락값 검증 |

StarUML에서는 포함시키는 UC에서 포함되는 UC 방향으로 연결한다. [StarUML Include 도구 안내](https://docs.staruml.io/working-with-uml-diagrams/use-case-diagram#include)

UC08과 UC10에는 이 구성에서 Actor 실선을 별도로 추가하지 않는다. UC11·UC12는 두 Actor와 직접 연결하고, 현재 없는 공통 처리까지 include로 가정하지 않는다.

**메뉴 순서와 화면 이동은 화면구성도·Storyboard에서 표현한다.** UC02를 조회했다고 UC03 저장이나 UC04 기록이 반드시 실행되는 것은 아니므로, 화면 이동 순서를 include 화살표로 연결하지 않는다. 일괄 담기와 직접 작성은 UC03 설명에 두며 이 권장안에서는 별도 extend 타원도 추가하지 않는다.

## 8. 제출 설명에 그대로 옮기면 안 되는 현재 시안의 표현

아래는 기능을 없애라는 뜻이 아니라, **설계한 기능과 검증된 구현·데이터를 구분하기 위한 확인 사항**이다.

| 확인한 상태 | 화면설계서·UC 설명 작성 기준 |
| --- | --- |
| 사례의 사업체명과 효과 수치는 고정된 예시이며 Make 작성 응답도 임의 예시라고 설명함 | ‘실제 매출 증가가 확인됨’이라고 쓰지 않음 UC11의 검증 전 상태를 표시하고 실제 자료 확보 후 교체 |
| 등록 자료 0건·0행인데 반영률 25%가 표시됨 | 추천 기준 항목도 반영률 계산에 포함되기 때문 실제 자료 적용률 25%가 검증됐다고 적지 않음 |
| CSV 등록 시 출처와 행 수를 저장하지만 분석 그래프의 자료는 고정된 예시 배열을 사용함 | ‘CSV 등록 → 실제 분석값과 추천 데이터 자동 갱신 완료’로 설명하지 않음 자료 등록·분석 적용·화면 상태 표시를 구분 |
| 마지막 확인 날짜는 2026년 9월 29일로 고정된 문구 | 자동으로 최신 확인 시점을 기록하는 기능으로 적지 않음 |
| 마케팅 제안 직접 추가는 계획 저장 팝업에 연결됨 | 제안 목록 자체의 생성·편집 기능이 완성된 것으로 적지 않음 현재는 UC03의 계획 직접 작성 |
| 기록 팝업의 날짜·활동은 계획에서 가져온 기본값 | 자동으로 실제 실행 사실을 확인하거나 성과를 수집한 것으로 적지 않음 |
| 임시 계정 채우기와 브라우저 저장을 사용함 | 업무 UC에 체험 계정 채우기를 추가하지 않음 서버 인증·저장까지 검증 완료한 것으로 표시하지 않음 |

확인 결과, 한 번에 담기는 초기 계획 2개에 현재 조건을 만족하는 제안 1개를 더해 3개로 만들었다. 이어 월별 직접 추가를 저장하자 계획이 4개가 됐지만 추천 카드 수는 1개로 유지됐다. 기록 팝업에서는 예정 날짜와 활동은 채워졌고 소요 시간·클릭·예약·쿠폰 수는 빈칸이었다. 이 결과를 바탕으로 위 기능을 구분했다.

## 9. StarUML에서 수정할 순서

1. 제출할 원본을 확인하고 기능 이름으로 기존 대표 UC와 대응시킨다. 저장소의 32개 세부 행동 초안과 설명서의 14개 기능을 혼동하지 않는다.
2. 시스템 경계 이름을 ‘제주 비수기 상권 마케팅 캘린더’로 유지한다.
3. Actor는 사업체 운영자와 서비스 운영자만 남긴다.
4. 방문 비교·소비 비교·실행 기록 입력·자료 출처 표시의 내용을 표에 따라 통합하고 중복 타원·선을 정리한다.
5. UC01·UC02·UC04·UC05 이름을 변경하고 UC03에 일괄 담기·직접 작성·삭제 흐름을 추가한다.
6. UC06은 이번 수정안의 제외 범위 주석으로 남기고 업무 타원에서 제외한다.
7. UC11·UC12 타원을 새로 만들고 두 Actor와 각각 실선으로 연결한다.
8. 6장의 Actor 연결표와 include 세 관계에 맞춰 선을 확인한다.
9. 4장·5장의 기본 흐름과 예외를 각 UC의 설명란에 반영한다.
10. 그림·설명서·프로젝트 기획서·화면설계서의 기능명과 범위를 대조한다.

32개 세부 행동 형식을 유지해야 하는 별도 사유가 없다면 이번 수정은 위 대표 UC 11개와 상세 설명으로 정리하는 편이 읽기 쉽다. 세부 행동 형식을 유지한다면 기존 UC02-1·UC02-2·UC02-3의 분석 내용을 UC01 범주로 옮기는 대응표부터 작성하고, UC03에는 일괄 담기·삭제, UC04에는 자동 채우기와 확인 절차, UC05에는 조회 흐름을 반영한다. 목표 숫자 32개를 맞추기 위해 기능을 쪼개거나 추가하지 않는다.

## 10. 최종 대조 체크리스트

- [ ] Actor가 사업체 운영자와 서비스 운영자 두 개인가
- [ ] ‘사용자’ Actor와 이를 향한 일반화 관계가 없는가
- [ ] UC11·UC12가 기존 화면의 사례·현황 영역과 연결되는가
- [ ] 월별 제안 조회와 일정표에 계획을 추가하는 동작을 구분했는가

- [ ] 미확보 값과 확인된 0건을 구분했는가
- [ ] UC05 조회를 위해 기록 입력을 강제하는 include가 없는가
- [ ] 서비스 운영자의 비공개 사업체 자료 접근에 권한 조건이 있는가
- [ ] include 세 관계의 대상과 방향이 맞는가
- [ ] UC06·온톨로지를 구현 대상 기능으로 다시 넣지 않았는가
- [ ] 사례 예시·반영률·고정 날짜를 검증된 실제 결과로 표현하지 않았는가
- [ ] 프로젝트 F02·F03에 월별 제안·일괄 담기·자동 채우기·사례 조회의 범위를 맞췄는가
- [ ] UC12의 자료 현황 조회를 프로젝트의 자료 기준·운영 지원 범위에 명시했는가

이 문서는 수정 가이드다. StarUML 원본, 프로젝트 기획서, 설명서, PPT 또는 Figma를 수정한 결과로 표시하지 않는다. 위 체크리스트도 실제 산출물들을 수정한 뒤 각각 확인한다.
