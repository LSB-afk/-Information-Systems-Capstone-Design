# Use Case 다이어그램 수정 가이드

- 작성일: 2026-09-28
- 프로젝트: 제주 비수기 상권 마케팅 캘린더
- 문서 상태: 수정 안내서 — 다이어그램 수정 완료를 의미하지 않음

## 수정 기준

- 수정 대상: 앞서 확인한 바탕 화면의 `제주 비수기 상권 마케팅 캘린더.mdj`
- 화면 기준: [수정된 화면설계서](../../00_제출/Red_SCREEN.md) · [PPTX](../../00_제출/Red%20화면설계서_20260927.pptx) · [PDF](../../00_제출/Red%20화면설계서_20260927.pdf)
- 원본 확인 결과: 대표 UC 10개와 별도로 그린 세부 기능 4개로 총 14개
- 이번 제출 기준: 중복 4개를 통합하고, 구현 범위에서 제외한 UC06 보고서 초안을 제출 도식에서 제외하면 **구현 대상 UC는 9개**
- 기존 UC 번호는 유지하며, UC06을 뺀 자리에 다른 UC의 번호를 당겨 붙이지 않음

이 가이드는 대표 UC 중심으로 정리하는 방식이다. 세부 기능을 별도 UC로 표현하는 것 자체가 잘못된 것은 아니다. 이번 수정의 목적은 수정된 PPT의 기능 범위·Actor·명칭과 다이어그램을 일치시키는 데 있다.

저장소의 `Red_USECASE.mdj`와 `Red_USECASE.md`에는 기존 32개 세부 행동을 기준으로 한 초안이 있으므로, 바탕 화면의 수정 대상 파일과 혼동하지 않는다.

## 1. 겹치는 타원 4개를 기존 UC에 합치기

| 삭제할 별도 타원 | 내용을 합칠 UC | 함께 정리할 연결선 |
| --- | --- | --- |
| 방문 비교 | UC01 지역별 방문 분석 조회 | 사업체 운영자·서비스 운영자와 연결된 선 삭제 |
| 소비 비교 | UC02 홍보 제안 조회 | 사업체 운영자·서비스 운영자와 연결된 선 삭제 |
| 실행 기록 입력 | UC04 사용 기록 입력 | 사업체 운영자·서비스 운영자와 연결된 선 삭제 |
| 자료 출처 표시 | UC10 자료 출처·기준 표시 | UC02에서 이 타원으로 연결된 include 선 삭제 |

해당 동작은 기존 UC의 설명에 남긴다. 화면의 방문·소비 비교, 기록 입력, 출처 표시는 유지한다.

확인한 원본에는 기존 UC01·UC02·UC04와 두 운영자 사이의 연결도 이미 있다. 삭제한 타원을 대신한다는 이유로 같은 연결선을 다시 추가하지 않는다.

## 2. UC 이름과 설명 수정하기

타원에는 아래 이름을 표시하고, 상세 내용은 설명란이나 주석에 작성한다.

| UC | 타원에 표시할 이름 | 설명에 반영할 내용 |
| --- | --- | --- |
| UC01 | 지역별 방문 분석 조회 | 지역·기간 선택, 지도·월별 그래프 조회, 지역·계절별 방문 비교 |
| UC02 | 홍보 제안 조회 | 방문·소비 비교, 홍보 시기·대상·상품 후보 조회, 추천 근거 확인 |
| UC03 | 3개월 홍보 일정표 관리 | 계획 작성·수정·삭제·저장·다시 보기 |
| UC04 | 사용 기록 입력 | 소요 시간, 추천 채택 여부, 실제 활동, 확보한 결과 입력 |
| UC10 | 자료 출처·기준 표시 | 사용한 자료의 출처·기준기간·집계 기준을 결과와 함께 표시 |

기존 설명 중 유효한 내용은 유지하면서 표의 항목을 반영한다. 특히 다음 두 항목을 확인한다.

- 현재 원본의 **‘기준 표시’**를 **‘자료 출처·기준 표시’**로 변경
- UC03 설명의 작성·수정·저장·다시 보기에 **‘삭제’** 추가

UC02는 현재 원본 설명에 방문·소비 비교가 포함되어 있으므로, 소비 비교를 UC02에 통합하는 기준을 유지한다.

## 3. 보고서 초안을 이번 제출 범위에서 제외하기

현재 수정된 PPT와 맞추려면 다음과 같이 정리한다.

1. `UC06 보고서 초안 작성` 타원을 제출 도식에서 제거
2. 사업체 운영자·서비스 운영자와 UC06 사이의 연결선 제거
3. 다이어그램 옆 주석에 아래 문구 작성

> UC06 보고서 초안 작성은 이번 제출의 구현 범위에서 제외함

**UC07을 UC06으로 바꾸는 식으로 번호를 다시 매기지 않는다.** PPT와 연결된 기존 번호를 유지한다. 이번 제출에서 제외한다는 뜻이며, 이후 도입 여부까지 확정한 것으로 표현하지 않는다.

## 4. Actor를 PPT와 같은 의미로 맞추기

### 4.1. 사용자 정의 수정

원본의 사용자 설명에 남아 있는 ‘일반 공개 사용자’, ‘정책 미확정’ 표현을 정리하고 다음과 같이 작성한다.

> 사용자: 로그인한 사업체 운영자와 서비스 운영자를 묶는 상위 Actor

사용자는 두 운영자의 공통 역할을 표현한다. 별도의 일반 회원 유형을 추가한다는 뜻이 아니다.

### 4.2. Actor와 UC 연결

| Actor | 직접 연결할 UC |
| --- | --- |
| 사용자 | UC01 지역별 방문 분석 조회, UC02 홍보 제안 조회 |
| 사업체 운영자 | UC03 3개월 홍보 일정표 관리, UC04 사용 기록 입력, UC05 계획 이행 확인 |
| 서비스 운영자 | UC03·UC04·UC05, UC07 CSV 자료 등록, UC09 추천 기준·근거 관리 |

UC08은 UC07의 include 관계로 연결한다. 이 가이드에서는 별도의 독립 실행 기능으로 추가하지 않는다.

### 4.3. Actor 사이의 일반화 연결

사업체 운영자와 서비스 운영자를 각각 사용자의 하위 Actor로 연결한다.

| 출발 Actor | 관계 | 도착 Actor |
| --- | --- | --- |
| 사업체 운영자 | Generalization | 사용자 |
| 서비스 운영자 | Generalization | 사용자 |

StarUML의 `Generalization` 도구를 선택하고, 각 운영자에서 사용자 방향으로 연결한다. 일반화 연결을 만든 뒤에는 두 운영자에서 UC01·UC02로 직접 이어진 중복 연결선을 정리한다. [StarUML Generalization 안내](https://docs.staruml.io/working-with-uml-diagrams/class-diagram#generalization)

### 4.4. 권한 조건 명시

사업체 운영자는 본인 사업체의 계획·기록을 이용한다. 서비스 운영자 옆에는 다음 주석을 붙인다.

> 사업체의 계획·기록은 관리 권한을 받은 사업체에 한해 처리함

서비스 운영자가 모든 사업체의 비공개 계획·기록을 자유롭게 처리하는 것으로 읽히지 않도록 한다.

## 5. include 연결 세 개 유지하기

| 출발 UC | 관계 | 도착 UC |
| --- | --- | --- |
| UC01 지역별 방문 분석 조회 | include | UC10 자료 출처·기준 표시 |
| UC02 홍보 제안 조회 | include | UC10 자료 출처·기준 표시 |
| UC07 CSV 자료 등록 | include | UC08 자료 기준·누락값 검증 |

StarUML의 `Include` 도구를 선택하고 출발 UC에서 포함되는 UC 방향으로 연결한다. [StarUML Include 안내](https://docs.staruml.io/working-with-uml-diagrams/use-case-diagram#include)

- UC01·UC02 결과에는 자료 출처·기준을 함께 표시
- CSV 등록에는 자료 기준·누락값 검증을 포함
- 온톨로지·근거 연결을 위한 별도 UC나 연결선은 추가하지 않음
- 기존 추천 이유와 자료 출처를 확인하는 기능은 유지

## 6. 최종적으로 남길 UC 9개

| ID | 최종 이름 |
| --- | --- |
| UC01 | 지역별 방문 분석 조회 |
| UC02 | 홍보 제안 조회 |
| UC03 | 3개월 홍보 일정표 관리 |
| UC04 | 사용 기록 입력 |
| UC05 | 계획 이행 확인 |
| UC07 | CSV 자료 등록 |
| UC08 | 자료 기준·누락값 검증 |
| UC09 | 추천 기준·근거 관리 |

UC06은 이번 제출 범위 제외 주석으로만 남긴다. 기능 개수를 맞추기 위해 다른 기능을 새로 추가하지 않는다.
