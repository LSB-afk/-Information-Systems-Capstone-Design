# ERD 수정 가이드

- 작성일: 2026-10-10
- 프로젝트: 제주 비수기 상권 마케팅 캘린더
- 기준 자료: 「[8주차] 정보시스템 프로젝트 설계 Data Modeling」 강의자료 56쪽 (아래에서는 'PDF'로 줄여 씀)
- 대상 파일: [Red_ERD.erwin](Red_ERD.erwin) (ERwin Data Modeler r7.3)
- 이미 고친 내용: [ERD 수정 내역](ERD_수정_내역.md)
- 화면 시안과 다른 곳: [ERD 프로토타입 대조 가이드](ERD_프로토타입_대조_가이드.md)

자동으로 고치지 못한 작업과 팀이 정해야 하는 부분을 PDF의 작성 방법에 맞춰 정리함 새 엔터티나 속성을 정해 두지 않았고, 바꿀지 말지는 3장의 질문으로 남김

## 1. 해야 할 일 순서

1. ERwin r7.3으로 [Red_ERD.erwin](Red_ERD.erwin)을 엶
2. 엔터티 배치를 원본과 같게 맞춤 → [2.1](#21-엔터티-배치-맞추기)
3. 물리 화면에 자료형이 보이게 함 → [2.2](#22-물리-화면에-자료형-표시)
4. 3장의 질문 7개를 팀에서 정하고, 바꾸기로 한 것만 ERwin에서 고침 → [3장](#3-팀이-정해야-하는-부분)
5. SQL 스키마를 만들고 테이블 명세서를 작성함 → [2.3](#23-sql-스키마와-테이블-명세서)
6. 4장 체크리스트로 마지막 확인을 함 → [4장](#4-완료-확인-체크리스트)

## 2. ERwin에서 직접 해야 하는 작업

### 2.1 엔터티 배치 맞추기

엔터티 위치와 관계선 경로는 ERwin만 바꿀 수 있는 값이라 자동으로 옮기지 못함 파일을 처음 열면 상자 7개가 왼쪽 위에 겹쳐 보임

1. Red_ERD.erwin을 엶
2. **Format → Stored Display Settings... → Layout 탭 → Layout Entire Diagram**을 눌러 상자를 펼침 모든 상자를 옮긴다는 경고(Caution!)가 나오면 확인을 누름
3. [원본/Logical ERD.erwin](<원본/Logical ERD.erwin>)을 함께 열어 두고 같은 자리로 상자를 끌어 옮김

| 줄 | 1열 | 2열 | 3열 | 4열 |
| --- | --- | --- | --- | --- |
| 윗줄 | 사용자 | 사업체 | 추천기준 | 홍보 제안 |
| 가운데 줄 | 자료 등록 현황 | 3개월 홍보 일정 | | |
| 아랫줄 | | 실행 결과 기록 | | |

4. 홍보 제안 → 3개월 홍보 일정 관계선은 원본처럼 홍보 제안 아래에서 내려와 일정의 오른쪽에 닿게 함 선이 꼬이면 같은 Layout 탭의 **Redraw All Relationship Lines**를 누름
5. File → Save로 저장함

### 2.2 물리 화면에 자료형 표시

PDF 51쪽, 52쪽, 54쪽의 물리 모델 예시는 컬럼 이름 옆에 자료형을 보여줌 이 표시 설정도 자동으로 바꿀 수 없었음

1. 도구 모음의 Logical/Physical 선택 상자에서 **Physical**을 고름 (PDF 44쪽의 Physical Model 전환과 같은 동작)
2. **Format → Display Level → Column**을 고름
3. **Format → Table Display → Column Datatype**에 체크함 PDF 54쪽처럼 NULL 여부까지 보이려면 **Null Option**도 체크함
4. 다시 **Logical**로 바꾸고 **Format → Display Level → Attribute**인지 확인함
5. 저장함

메뉴가 보이지 않으면 다이어그램의 빈 곳을 오른쪽 클릭해 같은 이름의 메뉴를 찾음

### 2.3 SQL 스키마와 테이블 명세서

PDF 47쪽, 53쪽, 55쪽의 순서를 따름

1. 물리 화면에서 **Tools → Forward Engineer → Schema Generation**을 엶
2. Preview로 CREATE TABLE 문장을 확인하고 .sql 파일로 저장함 저장소의 이 폴더에 두면 ERD와 함께 찾기 쉬움
3. 수업에서 제공한 테이블 명세서 서식으로 작성함 ERD의 물리 이름을 '컬럼명', 논리 이름을 '설명'에 쓰고 KEY 구분, Null, DataType, 길이는 Red_ERD.erwin의 설정과 같게 씀
4. FK 목록에는 관계 이름(BusinessUser 등), 관련 테이블, 컬럼명을 씀

## 3. 팀이 정해야 하는 부분

PDF 13쪽의 논리적 모델링 과정은 '상세 속성 추출 → 정규화 → 데이터 표준화' 순서임 아래 항목은 정규화 기준(PDF 29쪽부터 34쪽까지)으로 볼 때 확인이 필요한 부분임 내용 자체를 바꾸는 결정이라 고치지 않고 질문으로 남김

| 번호 | 대상 | 지금 상태 | PDF 기준 | 팀이 정할 질문 | 바꾸기로 하면 |
| --- | --- | --- | --- | --- | --- |
| Q1 | 추천기준의 '출처 및 기준 기간' (SOURCE_PERIOD_INFO) | 출처와 기준 기간을 한 속성에 저장 | 1정규형: 컬럼이 원자값 하나를 가짐 (32쪽) | 출처와 기간을 따로 보여주거나 비교해야 하는가 | 출처, 기준 기간을 각각의 속성으로 나눔 |
| Q2 | 실행 결과 기록의 '결과 및 수집 방법' (RESULT_MEMO) | 결과 내용과 수집 방법을 한 속성에 저장 | 1정규형 (32쪽) | 수집 방법을 따로 모아 볼 필요가 있는가 | 결과 내용, 수집 방법을 각각의 속성으로 나눔 |
| Q3 | 홍보 제안의 '주변 관광지', '추천 상품 후보' | 제안 하나에 값을 하나씩 저장 | 1차 정규화: 반복되는 속성 분할 (31쪽) | 제안 하나에 관광지나 상품을 여러 개 넣는가 | 여러 개면 별도 엔터티로 나누고 홍보 제안과 1:N 비식별 관계로 연결함 |
| Q4 | 실행 결과 기록의 '소요 시간' (SPENT_TIME_MIN) | 실행 기록마다 저장 | 3정규형: 비식별자 속성에 종속하는 속성 분할 (31쪽, 34쪽) | 이 값이 계획을 세우는 데 걸린 시간(UC04-1)인가, 활동을 실행하는 데 걸린 시간인가 | 계획 시간이면 일정 계획 ID에 종속하므로 3개월 홍보 일정으로 옮김 |
| Q5 | 실행 결과 기록의 '추천 채택 여부' (IS_ADOPTED) | 실행 기록마다 Y/N 저장 | 3정규형 (34쪽), 정규화 목적의 중복 최소화 (30쪽) | 일정의 홍보 제안 ID(직접 추가면 비어 있음)로 이미 알 수 있는 값인가 | 같은 뜻이면 지우거나 3개월 홍보 일정으로 옮김 다른 뜻이면 그대로 둠 |
| Q6 | 자료형의 길이, 월 값, 여부 값 | VARCHAR 길이는 임시값 대상 월, 기준 시작월, 기준 종료월은 DATE 방문 감소 기준율은 INTEGER 실행 여부, 추천 채택 여부는 CHAR(1) | 51쪽 규칙은 문자형 VARCHAR() 54쪽 예시는 여부 값에 CHAR(1) 사용 | 실제 자료의 최대 길이, 월 값을 DATE(그 달 1일)로 둘지, 기준율에 소수가 필요한지, 여부 값을 51쪽 규칙대로 VARCHAR로 맞출지 | Column Properties에서 Physical Data Type을 고침 (46쪽) |
| Q7 | 테이블 이름 | USERS, BUSINESS처럼 원본 이름 유지 | 51쪽, 52쪽, 53쪽, 55쪽 예시는 TBL_ 접두어를 쓰고 54쪽 예시는 쓰지 않음 규칙 문장에는 없음 | 수업에서 TBL_ 형식을 요구하는가 | Table Properties에서 이름을 바꾸고 테이블 명세서도 같은 이름으로 씀 |

ERwin에서 고치는 방법

- 속성 추가·삭제·이동: 논리 화면에서 엔터티 상자 안의 속성을 고침 (39쪽)
- 엔터티 추가와 관계 연결: 도구 모음의 엔터티 도구와 1:N(비식별) 관계 도구를 사용함 (37쪽, 40쪽) 관계 이름과 Null Option은 관계선 오른쪽 클릭 → Properties에서 [수정 내역 3장](ERD_수정_내역.md#3-관계-수정)과 같은 방식으로 정함 (42쪽)
- 자료형: 물리 화면에서 테이블 오른쪽 클릭 → Column Properties (46쪽)
- 바꾼 내용은 [ERD 수정 내역](ERD_수정_내역.md)에 날짜와 함께 적음

## 4. 완료 확인 체크리스트

- [ ] Model Properties의 Notation이 논리·물리 모두 IE임 (38쪽)
- [ ] 한 파일에서 Logical과 Physical 화면을 바꿔 볼 수 있음 (38쪽, 44쪽)
- [ ] 관계선이 모두 점선이고, 부모 쪽은 세로선, 자식 쪽은 동그라미와 까마귀발로 보임 PlanSuggestion만 부모 쪽에 동그라미가 있음 (27쪽, 40쪽, 43쪽)
- [ ] 관계 이름 6개가 R/ 번호가 아님 (42쪽)
- [ ] 물리 화면의 컬럼이 대문자이고 자료형이 함께 보임 (51쪽, 52쪽)
- [ ] CHAR(18)로 남은 컬럼이 없음
- [ ] 엔터티 배치가 원본과 같고 상자나 선이 겹치지 않음
- [ ] 3장의 질문 7개에 대해 정한 내용을 기록함
- [ ] Schema Generation으로 만든 SQL과 테이블 명세서가 ERD와 같음 (47쪽, 53쪽, 55쪽)
- [ ] 팀원 모두 같은 ERwin 버전(r7.3)을 사용함 ERwin 15.2에서는 원본 파일이 열리지 않았음
