## 실제 적재 결과

14:49 KST에 원본 해시·구조·중복 월의 금액·고객군 합계를 검사하고 한 트랜잭션으로 적재함 커밋 후 별도 실행에서 기존 내용과 다시 대조함

```text
최초: snapshots=3 regions=43 observations=60 shares=88 insertedRows=210
반복: snapshots=3 regions=43 observations=60 shares=88 insertedRows=0
```

| 테이블 | 적재 후 행 수 | 의미 |
| --- | ---: | --- |
| IJTO_DATA_SNAPSHOT | 3 | JSON 원문 전체와 저장소·커밋·파일 경로·SHA-256·수집일 |
| REGION | 43 | 원천의 읍면동 방문 코드 10자리와 지역 이름 |
| REGION_MONTHLY_STAT | 60 | 구좌 방문 16행·음식점 소비 44행 |
| REGION_CONSUMPTION_STAT | 88 | 구좌 음식점 월별 내국인·외국인 비중 |
| DATA_SOURCE | 2 | 방문 자료·소비 자료의 출처와 관측 기간 |
| DATA_VALIDATION_RESULT | 10 | 각 자료의 기간·집계·지역 코드·누락·제공 기준 검사 |
| USERS | 2 | 기존 공개 시연 형식의 사업체 운영자·서비스 운영자 |
| BUSINESS | 1 | 실제 사업체 정보가 아닌 구좌 시연 음식점 |
| BUSINESS_PERMISSION | 1 | 시연 서비스 운영자의 관리 권한 |
| RECOMMENDATION_CRITERIA | 0 | 기준을 임의로 만들지 않음 |
| PROMO_SUGGESTION | 0 | 없는 근거로 제안을 만들지 않음 |
| PROMO_SUGGESTION_ITEM | 0 | 제안 항목 없음 |
| PROMO_PLAN | 0 | 가상 계획 없음 |
| EXECUTION_RECORD | 0 | 가상 실행 결과 없음 |
| 합계 | 210 | 적재 후 별도 DB 조회 결과 |

DB는 테이블 14개·시퀀스 9개이며 [확장 SQL과 ERD 차이](../../04_아키텍처/ERD/ERD_실제데이터_확장.md)를 함께 기록함 기존 ERwin 편집 원본에는 이번 확장을 아직 반영하지 않음

최초 이관 시 출처 등록일에 시각까지 저장돼 같은 날 나중에 올린 CSV가 최신 자료로 선택되지 않는 차이를 확인함 현재 이관기는 기존 CSV와 같이 `TRUNC(SYSDATE)`로 날짜만 저장함 이미 적재한 두 출처에는 [등록일 보정 SQL](../../08_개발/jeju-calendar/db/05_normalize_ijto_registration_date.sql)을 적용함 다른 출처와 원본 스냅샷의 적재 시각은 바꾸지 않음

## 수치와 의미 확인

| 확인 대상 | 원천 값 | Oracle·API 값 |
| --- | --- | --- |
| 구좌 2025년 1월 방문 | 493,209명 | 49.3209만 명 |
| 구좌 2025년 1월 음식점 소비 | 4,546,311,310원 | 45.46311310억 원 |
| 구좌 2023년 1월 음식점 소비 | 세 고객군 합계 3,761,568,382원 | 37.61568382억 원 |
| 구좌 2025년 10월 음식점 소비 비중 | 월별 실제 소비금액으로 계산 | 내국인 92.35%·외국인 7.65% |
| 없는 방문 월 | 2025년과 2026년의 9월부터 12월까지 원천 값 없음 | `null` 유지 |

- 월별 값은 Oracle `NUMBER`·Java `BigDecimal`로 처리함 만 명·억 원 단위를 유지하면서 정수로 잘라 저장하지 않음 JSON의 소수 끝 0이 생략돼도 수치는 같음
- 방문은 2025년과 2026년 각각 1월부터 8월까지임 소비는 2023년부터 2025년까지의 36개월과 2026년 1월부터 8월까지임
- 43개 지역의 계절지수는 원본 CLOB에 보존함 실제 월별 총량 60행은 구좌 자료이며 43개 지역 모두의 실제 월별 총량이 확보된 상태는 아님
- 소비 업종은 `RESTAURANT`임 내국인은 내국인 관광객과 도민의 합계이며 카페 고객이나 개별 가게 손님 수로 해석하지 않음
- 다년 시간대 비중·관광지 후보·카드 이용건수·세 고객군의 원래 값·원천 경고·이용 조건 미확인 표시는 원본 JSON에 유지함 특정 연도의 관측값으로 바꾸지 않음
- 스냅샷은 CLOB을 다시 읽어 원문 전체가 같은지 확인함 파일별 SHA-256·바이트 수는 [manifest.json](../../02_제품/데이터/ijto_20261027/manifest.json)에 기록함

## 실행 서버 API 확인

`http://localhost:8080`의 실행 서버에 시연 사업체 계정으로 로그인한 뒤 아래 요청이 모두 HTTP 200으로 응답함 응답의 실제 수치·단위·출처와 누락 월을 확인함

| 요청 | 확인 결과 |
| --- | --- |
| `POST /api/auth/login` | 시연 사업체 계정 로그인 성공 |
| `GET /api/businesses` | 구좌 시연 음식점과 `5011025600` 지역 코드 |
| `GET /api/analysis/trend?regionCode=5011025600&year=2025&metric=VISIT` | 1월 49.3209만 명·9월 이후 `null`·원본 커밋 출처 |
| `GET /api/analysis/trend?regionCode=5011025600&year=2025&metric=SPEND` | 1월 45.46311310억 원·12개월 소비 값 |
| `GET /api/analysis/consumption?regionCode=5011025600&year=2025&category=RESTAURANT` | 방문·소비 단위 구분과 10월 음식점 소비 비중 |
| `GET /api/overview` | 최신 2026년 실제 방문 값·없는 달 유지 |
| `GET /api/suggestions` | 추천 기준 미등록 안내·제안 0개 |

일정 기준은 2026년 10월부터 12월까지임 이 묶음에는 해당 기간의 2026년 관측값이 없어 일부 비교와 제안이 비어 있음 2025년을 선택하면 확보된 음식점 소비와 비중을 조회할 수 있음 카페 비중과 특정 연도 시간대 비중은 미확보 상태임

브라우저 자동화 연결을 사용할 수 없어 이번 적재 후 서버 화면을 직접 조작하는 검증은 수행하지 못함 위 결과는 실행 서버 HTTP 응답 확인 범위임
